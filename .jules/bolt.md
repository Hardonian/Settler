## 2024-05-24 - Resolve N+1 query issue for mapping template updates
 **Learning:** When optimizing an N+1 query that uses a database limit (\`take: 10\`), doing bounded \`Promise.all\` queries is one way, but a better batch fetch approach is to fetch all records with an \`IN\` clause (if safe regarding OOM), and then enforce the bounded limits with an in-memory reduce/grouping operation. Memory constraints should only dictate avoiding \`IN\` if explicitly known to cause OOM errors (as when fetching entire multi-million row tables), whereas fetching \`mappingTemplate\` updates for ~100 mapping names is typically well within memory limits.
 **Action:** Prioritize batching via \`IN\` clauses accompanied by in-memory grouping and slicing when optimizing N+1 queries, reserving \`Promise.all\` fallback for unbounded queries or where memory exhaustion is a demonstrated risk.
