# Data Processing Addendum (DPA) Template

**Last Updated:** 2025-01-20  
**Status:** Revenue Bootstrap - Active  
**Purpose:** Data Processing Addendum template for GDPR compliance

## Overview

This is a **lightweight DPA template** designed for:

- GDPR compliance requirements
- Clear data processing terms
- Standard data protection clauses
- Easy execution with MSA

**Philosophy:** Keep it simple, comply with GDPR, make it easy to execute.

**Legal Note:** This is a template. Have legal counsel review before use.

---

## Data Processing Addendum

**Parties:**

- **Data Controller:** [Customer Name] ("Controller")
- **Data Processor:** Settler, Inc. ("Processor")

**Effective Date:** [Date]

**Purpose:** This DPA governs data processing under the Master Services Agreement.

---

## 1. Definitions

### 1.1 Terms

- **Personal Data:** Any information relating to an identified or identifiable natural person
- **Processing:** Any operation performed on Personal Data
- **Controller:** Entity that determines purposes and means of processing
- **Processor:** Entity that processes Personal Data on behalf of Controller

### 1.2 GDPR Terms

Terms defined in GDPR have the same meaning in this DPA.

---

## 2. Processing of Personal Data

### 2.1 Processing Purpose

Processor will process Personal Data only to:

- Provide services under the Master Services Agreement
- Comply with Controller's instructions
- Comply with applicable data protection laws

### 2.2 Processing Scope

Processor will process Personal Data:

- **Categories:** Transaction data, user data, API data
- **Types:** Names, emails, transaction details, API keys
- **Subjects:** Controller's customers, users, employees

### 2.3 Processing Duration

Processor will process Personal Data for the duration of the Master Services Agreement, then delete as specified in Section 5.

---

## 3. Processor Obligations

### 3.1 Processing Instructions

Processor will:

- Process Personal Data only per Controller's instructions
- Not process Personal Data for purposes other than specified
- Notify Controller if instructions violate data protection laws

### 3.2 Security Measures

Processor will implement:

- **Technical Measures:** Encryption, access controls, monitoring
- **Organizational Measures:** Staff training, access restrictions, audit logs
- **Physical Measures:** Secure data centers, access controls

### 3.3 Confidentiality

Processor will:

- Ensure personnel are bound by confidentiality obligations
- Not disclose Personal Data to third parties (except as required by law)
- Maintain confidentiality after termination

---

## 4. Controller Obligations

### 4.1 Lawful Basis

Controller warrants that:

- Processing has lawful basis under GDPR
- Controller has necessary consents (if required)
- Controller complies with data protection laws

### 4.2 Instructions

Controller will:

- Provide clear processing instructions
- Not instruct Processor to violate data protection laws
- Respond to Processor's requests for clarification

---

## 5. Data Subject Rights

### 5.1 Rights Requests

Processor will:

- Assist Controller in responding to data subject rights requests
- Provide Personal Data in structured, commonly used format
- Delete Personal Data upon Controller's request

### 5.2 Rights Implementation

Processor will implement:

- **Access:** Provide access to Personal Data
- **Rectification:** Correct inaccurate Personal Data
- **Erasure:** Delete Personal Data upon request
- **Portability:** Export Personal Data in portable format
- **Objection:** Stop processing upon objection (if applicable)

---

## 6. Data Transfers

### 6.1 Transfer Restrictions

Processor will not transfer Personal Data outside EEA unless:

- Adequate safeguards are in place
- Standard Contractual Clauses are executed
- Controller has consented to transfer

### 6.2 Transfer Mechanisms

Processor will use:

- **Standard Contractual Clauses:** EU-approved clauses
- **Adequacy Decisions:** Countries with adequacy decisions
- **Other Mechanisms:** As approved by Controller

---

## 7. Sub-Processors

### 7.1 Sub-Processor Authorization

Controller authorizes Processor to engage sub-processors:

- **Infrastructure:** Cloud providers (AWS, Supabase, Vercel)
- **Services:** Support tools, analytics tools
- **List:** Available upon request

### 7.2 Sub-Processor Requirements

Processor will:

- Ensure sub-processors comply with this DPA
- Notify Controller of new sub-processors (30 days' notice)
- Allow Controller to object to new sub-processors

---

## 8. Data Breach

### 8.1 Breach Notification

Processor will notify Controller of data breaches:

- **Timing:** Without undue delay, within 72 hours if feasible
- **Content:** Nature of breach, categories affected, likely consequences
- **Updates:** Regular updates on breach investigation and remediation

### 8.2 Breach Response

Processor will:

- Investigate breach promptly
- Take reasonable steps to mitigate breach
- Assist Controller in breach notification (if required)

---

## 9. Data Retention & Deletion

### 9.1 Retention Period

Processor will retain Personal Data:

- **During Term:** For duration of Master Services Agreement
- **After Termination:** 30 days (for data export)
- **After Retention:** Permanently deleted

### 9.2 Deletion

Processor will:

- Delete Personal Data upon Controller's request
- Delete Personal Data after retention period
- Confirm deletion in writing

---

## 10. Audits & Compliance

### 10.1 Audit Rights

Controller may audit Processor's compliance:

- **Frequency:** Annually (or upon reasonable suspicion of non-compliance)
- **Scope:** Data processing activities, security measures
- **Process:** Reasonable notice, during business hours, Processor's costs

### 10.2 Compliance Certifications

Processor will maintain:

- **SOC 2 Type II:** When obtained
- **ISO 27001:** Aligned (not certified)
- **Other Certifications:** As specified in Master Services Agreement

---

## 11. Liability & Indemnification

### 11.1 Liability

Processor's liability for data protection breaches is limited as specified in Master Services Agreement.

### 11.2 Indemnification

Processor will indemnify Controller against:

- Third-party claims arising from Processor's breach of this DPA
- Regulatory fines arising from Processor's breach of this DPA

---

## 12. General Terms

### 12.1 Entire Agreement

This DPA is part of the Master Services Agreement and supplements (not replaces) its terms.

### 12.2 Modification

This DPA may be modified only by written agreement signed by both parties.

### 12.3 Governing Law

This DPA is governed by [State] law and GDPR.

### 12.4 Termination

This DPA terminates with the Master Services Agreement.
