# Settler: System Specification & Operational Truth Matrix ## 1. FULL ENTITY SCHEMA ### Core Operations - **ReconciliationItem** - `id`: UUID (Primary Key) - `status`: Enum (ReconciliationStatus) - `source_a_id`: UUID (FK to Transaction) - `source_b_id`: UUID (FK to Transaction) - `variance_amount`: Decimal - `variance_currency`: ISO-4217 - `match_rule_id`: UUID (Optional, if auto-matched) - `assigned_to`: UUID (FK to User) - `tenant_id`: UUID (Shard Key) - **Transaction** - `id`: UUID - `external_id`: String (Source system ID) - `connector_id`: UUID - `amount`: Decimal - `currency`: ISO-4217 - `timestamp`: UTC DateTime - `metadata`: JSONB (Source-specific fields) - `ledger_state`: Enum (Posted, Pending, Voided) - **Exception** - `id`: UUID - `reconciliation_item_id`: UUID - `severity`: Enum (Critical, Warning, Info) - `root_cause_category`: Enum (Timing, Amount, Currency, Missing_Record) - `sla_deadline`: UTC DateTime - `owner_id`: UUID ### System & Admin - **Run (Job/Process)** - `id`: UUID - `job_type`: Enum (Ingest, Recon, Export) - `environment`: Enum (Production, Sandbox) - `status`: Enum (RunStatus) - `started_at`: UTC DateTime - `completed_at`: UTC DateTime (Nullable) - **Connector** - `id`: UUID - `provider`: String - `health_status`: Enum (Healthy, Degraded, Failed) - `last_sync_at`: UTC DateTime - `config`: Encrypted JSON - **Rule** - `id`: UUID - `priority`: Integer - `logic`: JSON (AST for conditions) - `is_active`: Boolean - `version`: Integer --- ## 2. STATE MACHINES ### A. ReconciliationItem Lifecycle - **UNMATCHED**: Default state on ingestion. No counterpart found. - **CANDIDATE_MATCH**: System identified potential matches based on loose rules. - **MATCHED**: 1:1 match confirmed by deterministic rule or manual action. - **PARTIALLY_MATCHED**: 1:N or M:N match requiring manual variance resolution. - **VERIFIED**: Post-match audit step completed. (Immutable) - **ESCALATED**: Flagged for senior review due to high variance or risk. - **REVERSED**: Match undone due to source data correction. **Forbidden Transitions:** - `VERIFIED` -> `UNMATCHED` (Must reverse first) - `MATCHED` -> `MATCHED` (No-op check) ### B. Exception Lifecycle - **OPEN**: Created automatically on recon failure. - **TRIAGED**: Categorized but not yet assigned. - **ASSIGNED**: Owner attached. - **IN_PROGRESS**: Owner has actively engaged with investigation. - **RESOLVED**: Variance explained or match forced. - **CLOSED**: Final audit sign-off. - **REOPENED**: New data invalidates resolution. --- ## 3. ACTION CONTRACT TABLE | Action | Preconditions | Side Effects | Audit Requirement | | :--- | :--- | :--- | :--- | | **Match (Manual)** | Item = `UNMATCHED`, User has `OPERATOR` role | Create `ReconciliationItem`, Link Transactions, Set Status `MATCHED` | Actor, Timestamp, Record IDs, Variance | | **Escalate** | Item != `VERIFIED`, Active Exception exists | Status -> `ESCALATED`, Notify Owner, Update SLA | Reason for escalation | | **Retry Run** | Run = `FAILED` or `PARTIAL_SUCCESS` | New `Run` entry, Reset Processing Flags, Clear Stale Logs | Original Run ID Reference | | **Override Rule** | Rule = `INACTIVE` or Admin Access | Update `Rule.logic`, Increment `version`, Invalidate Caches | Full Logic Diff | --- ## 4. FAILURE MODE MATRIX | Scenario | Detection Method | UI Signal | Recovery Path | | :--- | :--- | :--- | :--- | | **Duplicate Ingestion** | Unique Constraint on `external_id` | Warning Banner on Connector Page | Deduplication Job / Manual Purge | | **Connector Lag** | `last_sync_at` > `expected_frequency` | "Stale Data" Badge on Dashboard | Force Sync / Re-auth | | **Conflicting Rules** | Rule Engine Validation | "Logic Overlap" Warning in Editor | Adjust Priority or Conditions | | **Run Timeout** | Watchdog Process | "Timed Out" Status on Run Detail | Manual Kill & Restart | --- ## 5. UI TRUTH VALIDATION FINDINGS - **Finding 1**: The *Executive Dashboard* implies "Overall Match Rate" is real-time. **Correction**: Must include a "Data Freshness" indicator showing if runs are currently processing or stale. - **Finding 2**: *Investigation View* allows "Force Match" on any row. **Correction**: Precondition check required to ensure user doesn't match two records from the same source system (invariant violation). - **Finding 3**: *Run Monitor* shows "Partial Success". **Correction**: The UI must explicitly link to the specific `Exception` IDs generated by the failed records in that run. --- ## 6. SYSTEM INVARIANTS 1. **Sum(Source_A) - Sum(Source_B) == Variance**: Always true for any matched pair/group. 2. **Exclusivity**: A transaction ID can only belong to exactly ONE active `ReconciliationItem`. 3. **Audit Trail Immutability**: No `AuditEvent` record can be modified or deleted. 4. **Tenant Isolation**: Every query must include `tenant_id` in the `WHERE` clause. --- ## 7. DEGRADED STATE SPECIFICATION - **Partial Data Mode**: Triggered when a `Run` ends in `PARTIAL_SUCCESS`. - **UI Behavior**: Yellow banner on top of Workspace: "Showing partial results. [View Details]". - **Blocked Actions**: "Period Close" is disabled until data is complete. - **Stale Connector Mode**: Triggered when sync is >1h overdue. - **UI Behavior**: Red dot on connector icon. Dashboard metrics show "Stale" watermark.
