⚡ [performance improvement N+1 Query in predictMappingVolatility]

💡 **What:** Replaced the N+1 database queries in `predictMappingVolatility` (a `findMany` inside a for loop) with a single batched `findMany` query using the `in` operator, followed by in-memory grouping using a Map.

🎯 **Why:** Calling the database sequentially inside a loop creates an N+1 query pattern, which drastically increases database load, adds network latency overhead per query, and degrades performance. By fetching the history for all mappings in a single batched query, we significantly reduce execution time and avoid overloading the database connection pool.

📊 **Measured Improvement:** In a local benchmark fetching 100 mappings with mocked database latency (2ms per simulated roundtrip query), execution time dropped from an average of ~222ms per run to ~2.4ms per run.
