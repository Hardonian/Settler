# Test Data Foundry

## Primitive map (repo reality)

- **Trace and correlation:** `packages/web/src/lib/observability/trace.ts`, `packages/web/middleware.ts`.
- **Problem+JSON style responses:** `packages/web/src/lib/api/v1/recon/core.ts`, `packages/web/src/lib/api/safe-error-handler.ts`.
- **CLI command architecture:** `packages/cli/src/index.ts` dynamic command registry.
- **Verification primitives:** root `package.json` scripts `verify:routes`, `verify:replay`, `verify:policy`, `verify:determinism`.
- **Artifact convention:** `artifacts/` directory already used by multiple verify/test scripts.

## Foundry architecture added in this change

- New CLI command group: `settler foundry`.
- File-backed data store rooted at `artifacts/foundry/`:
  - `datasets.json`
  - `items.json`
  - `runs.json`
  - `foundry_report.json`
  - `foundry_report.csv`
  - `failing_items.json`
- Versioned entities implemented in `packages/cli/src/lib/foundry.ts`:
  - `Dataset`
  - `DatasetItem`
  - `DatasetRun`

## Datasets currently implemented

- `core_vectors` (`VECTORS`): deterministic route/replay/policy/drift vector cases.
- `metamorphic_suite` (`METAMORPHIC`): seeded transform variants from base vectors.
- `fault_injection_suite` (`FAULT_INJECTION`): gated fault labels (`FOUNDRY_FAULTS=1` required to run).

## Determinism controls

- Stable hash ids generated by sorted-key serialization (`stableStringify` + sha256).
- Stable item ordering by `item_id`.
- Reproducibility metadata persisted for each item (`seed`, `config_hash`).
- Artifact file names are fixed.

## Tenant safety

- Dataset model supports `tenant_scope` and `tenant_id`.
- Core bootstrap defaults to `GLOBAL` scope.
- Tenant-specific datasets can be generated by passing tenant context from caller.
