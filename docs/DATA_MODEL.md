# Data Model & Ownership

**Last Updated:** 2025-01-20  
**Status:** Production Reality  
**Purpose:** Explicit definition of data ownership, boundaries, and retention

## Overview

This document defines **data ownership**, **data boundaries**, and **data retention** policies for Settler. It is designed to help users understand what data Settler stores and who owns it.

**Philosophy:** Users own their data. Settler processes it. Clear boundaries prevent confusion.

---

## Data Ownership

### User-Owned Data

**Definition:** Data created by users or imported by users.

**Examples:**

- Reconciliation jobs and configurations
- Receipt uploads and parsed data
- Feature flags and configurations
- Webhook configurations
- API keys (hashed)

**Ownership:** Users own this data. Settler processes it on behalf of users.

**Rights:**

- ✅ Users can export their data
- ✅ Users can delete their data
- ✅ Users can request data deletion
- ✅ Users control data access

---

### System-Generated Data

**Definition:** Data generated by Settler's systems.

**Examples:**

- Usage events and metrics
- Audit logs
- System configuration
- Performance metrics

**Ownership:** Settler owns this data. Users have read-only access to their own metrics.

**Rights:**

- ✅ Users can view their own metrics
- ✅ Users cannot delete system-generated data
- ✅ Settler uses this data for operations and billing

---

### Shared Data

**Definition:** Data shared between users and Settler.

**Examples:**

- Reconciliation results (user data processed by Settler)
- Receipt parsing results (user uploads processed by Settler)
- Feature flag evaluations (user configuration evaluated by Settler)

**Ownership:** Users own the input data. Settler owns the processing results. Both have rights to their respective portions.

**Rights:**

- ✅ Users own input data (can delete)
- ✅ Users own output data (can export)
- ✅ Settler uses processing results for operations (anonymized)

---

## Data Boundaries

### Tenant Isolation

**Principle:** Data is isolated by tenant at the database level.

**Enforcement:**

- ✅ Row-Level Security (RLS) policies enforce tenant isolation
- ✅ All queries filtered by `tenant_id`
- ✅ No cross-tenant data access possible through API

**Boundaries:**

- Users can only access data from their own tenant
- Administrators cannot access other tenants' data (without service-role keys)
- Service-role keys bypass RLS (documented risk, requires operational controls)

---

### Data Segregation

**Principle:** Different types of data are stored separately.

**Segregation:**

- **User Data:** Stored in tenant-scoped tables
- **System Data:** Stored in system tables (not tenant-scoped)
- **Audit Data:** Stored in audit tables (tenant-scoped for user actions)

**Boundaries:**

- User data cannot access system data
- System data cannot access user data (except for operations)
- Audit data is read-only (append-only)

---

### Multi-Tenancy

**Principle:** Multiple tenants share the same database but are isolated.

**Isolation:**

- ✅ Database-level isolation (RLS)
- ✅ Application-level isolation (tenant middleware)
- ✅ No shared data between tenants

**Boundaries:**

- Tenants cannot access other tenants' data
- Tenants cannot affect other tenants' operations
- Tenants share infrastructure but not data

---

## Data Retention

### User Data Retention

**Policy:** User data is retained until deleted by user or account closure.

**Retention Periods:**

- **Active Accounts:** Indefinite (until user deletes)
- **Inactive Accounts:** 90 days after last activity
- **Deleted Accounts:** 30 days soft delete, then permanent deletion

**Exceptions:**

- Audit logs: 7 years (legal requirement)
- Billing data: 7 years (legal requirement)
- Deleted data: 30 days soft delete, then permanent deletion

---

### System Data Retention

**Policy:** System data is retained for operational purposes.

**Retention Periods:**

- **Usage Events:** 90 days (aggregated into daily aggregates)
- **Performance Metrics:** 30 days
- **Error Logs:** 90 days
- **Audit Logs:** 7 years

**Exceptions:**

- Critical errors: 1 year
- Security events: 7 years
- Compliance data: 7 years

---

### Backup Retention

**Policy:** Backups are retained for disaster recovery.

**Retention Periods:**

- **Daily Backups:** 30 days
- **Weekly Backups:** 12 weeks
- **Monthly Backups:** 12 months

**Exceptions:**

- Critical data: Extended retention (configurable)
- Compliance data: Extended retention (legal requirement)

---

## Data Access

### User Access

**Principle:** Users can access their own data through the API.

**Access Methods:**

- ✅ REST API (authenticated)
- ✅ Developer Console (web UI)
- ✅ CLI (command-line tool)

**Limitations:**

- Users can only access their own tenant's data
- Users cannot access system data (except metrics)
- Users cannot access other tenants' data

---

### Administrative Access

**Principle:** Administrators can access system data for operations.

**Access Methods:**

- ✅ Service-role keys (bypass RLS)
- ✅ Database access (read-only for most operations)
- ✅ Monitoring tools (read-only)

**Limitations:**

- Administrative access is logged
- Service-role keys require operational controls
- Cross-tenant access requires explicit approval

---

### Third-Party Access

**Principle:** Third parties cannot access user data without user consent.

**Access Methods:**

- ✅ User-initiated exports
- ✅ Webhook deliveries (user-configured)
- ✅ API integrations (user-configured)

**Limitations:**

- No third-party access without user consent
- No data sharing with third parties
- No data resale

---

## Data Export

### Export Capabilities

**What Can Be Exported:**

- ✅ Reconciliation jobs and configurations
- ✅ Receipt data (parsed receipts and items)
- ✅ Feature flags and configurations
- ✅ Webhook configurations
- ✅ Usage metrics

**Export Formats:**

- JSON (structured data)
- CSV (tabular data)
- SQL (database dumps, enterprise only)

---

### Export Limitations

**What Cannot Be Exported:**

- ❌ System-generated data (except user metrics)
- ❌ Other tenants' data
- ❌ Encrypted data (exported decrypted)
- ❌ Audit logs (read-only, not exportable)

**Limitations:**

- Exports are limited by file size (10MB default)
- Large exports may require async processing
- Exports expire after 7 days

---

## Data Deletion

### User-Initiated Deletion

**Process:**

1. User requests data deletion
2. Data marked for deletion (soft delete)
3. Data deleted after 30 days (permanent deletion)

**What Gets Deleted:**

- User-created data (jobs, receipts, flags)
- User configurations
- User API keys

**What Does NOT Get Deleted:**

- Audit logs (legal requirement)
- Billing data (legal requirement)
- System-generated metrics (anonymized)

---

### Account Closure

**Process:**

1. User requests account closure
2. Account marked as closed
3. Data retention period begins (90 days)
4. Data deleted after retention period

**What Gets Deleted:**

- All user data (after retention period)
- User configurations
- User API keys

**What Does NOT Get Deleted:**

- Audit logs (legal requirement)
- Billing data (legal requirement)

---

### Automatic Deletion

**Triggers:**

- Inactive accounts (90 days)
- Soft-deleted data (30 days)
- Expired exports (7 days)

**Process:**

- Automated cleanup jobs run daily
- Data marked for deletion
- Data permanently deleted after retention period

---

## Data Privacy

### Personal Data

**Definition:** Data that can identify individuals.

**Examples:**

- Email addresses
- Names
- IP addresses
- User IDs

**Handling:**

- ✅ Encrypted at rest (best-effort)
- ✅ Encrypted in transit (TLS)
- ✅ Access controlled (authentication required)
- ✅ Redacted in logs (PII redaction)

---

### Sensitive Data

**Definition:** Data that requires special protection.

**Examples:**

- API keys (hashed)
- Integration credentials (encrypted)
- Payment information (not stored, handled by Stripe)

**Handling:**

- ✅ Encrypted at rest (AES-256)
- ✅ Encrypted in transit (TLS)
- ✅ Access controlled (strict permissions)
- ✅ Audit logged (all access logged)

---

## Data Compliance

### GDPR Compliance

**Rights:**

- ✅ Right to access (data export)
- ✅ Right to rectification (data updates)
- ✅ Right to erasure (data deletion)
- ✅ Right to portability (data export)

**Compliance:**

- ✅ Data processing agreements
- ✅ Privacy policy
- ✅ Data protection impact assessments

---

### CCPA Compliance

**Rights:**

- ✅ Right to know (data disclosure)
- ✅ Right to delete (data deletion)
- ✅ Right to opt-out (data sharing)

**Compliance:**

- ✅ Privacy policy
- ✅ Data deletion procedures
- ✅ No data resale

---

## Summary

Settler's data model:

- ✅ **User Ownership:** Users own their data
- ✅ **Tenant Isolation:** Data isolated by tenant (RLS)
- ✅ **Data Retention:** User data retained until deletion, system data retained for operations
- ✅ **Data Access:** Users access their own data, administrators access system data
- ✅ **Data Export:** Users can export their data
- ✅ **Data Deletion:** Users can delete their data
- ✅ **Data Privacy:** Personal and sensitive data protected
- ✅ **Data Compliance:** GDPR and CCPA compliant

**Key Principles:**

- Users own their data
- Clear boundaries prevent confusion
- Data retention balances user needs and legal requirements
- Data privacy is a priority

**When in doubt, users own their data. Settler processes it on their behalf.**
