💡 **What:** Replaced the sequential `for...of` loop in `TTLWorker.run()` with parallel batched processing using `Promise.all`. The array of active tenants is divided into batches sized by `config.maxConcurrentDeletes` (default 10) to control load on the database while processing multiple tenants concurrently.

🎯 **Why:** To solve an N+1 query issue. The previous implementation sequentially processed each tenant (`await this.processTenant()`), which was a massive bottleneck as the operations block each other over network and DB latency.

📊 **Measured Improvement:**
Simulated processing of 5,000 tenants with a mock 5ms latency:
- Sequential Baseline: 26,107 ms
- Parallel Batched (chunk size 100): 271 ms
- Improvement: ~96x faster (significantly less network idling)
