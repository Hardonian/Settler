# Executive Summary

**As of:** 2026-09-21

Settler is a deterministic reconciliation and exception-resolution system for platforms and
finance teams working across payment processors, commerce systems, banks, and ledgers.

## Product evidence

- A TypeScript/Rust monorepo implements reconciliation, adapters, API/console surfaces, replay,
  proofpacks, SDK/CLI tooling, and tenant-control guardrails.
- The canonical release gate passes lint, type checks, builds, CI tests, contract checks, route
  truth, policy checks, tenant coverage, and cross-tenant application tests.
- Determinism, replay, and proofpack contracts have named, repeatable verification commands.

## Commercial focus

The initial workflow is processor payout to bank deposit to ledger, including fees, refunds,
chargebacks, timing differences, and foreign exchange. The intended customer is a vertical software
or finance platform with multiple rails and a recurring finance-operations exception workload.

## Current boundary

Repository capability is ahead of company evidence. The active evidence room does not contain
source-backed paying-customer, revenue, retention, reference, partnership, named-team,
certification, or legal-opinion evidence. Live target RLS verification is credential-blocked.

The operating objective is to earn paid production proof, repeatable onboarding, a permissioned
exception-resolution corpus, independent security evidence, and clean corporate/IP records. Until
then, Settler should be presented as technically credible but commercially unproven.
