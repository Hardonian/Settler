# Packaging and Plan Architecture

## Canonical internal sell model

Settler is sold as a **reconciliation-intelligence and exception/evidence operating system**.

### Sellable offers (current truth)

| Offer      | Target                           | Commercial shape                                          | Notes                                   |
| ---------- | -------------------------------- | --------------------------------------------------------- | --------------------------------------- |
| Starter    | early operators                  | monthly platform fee + usage                              | standard terms only                     |
| Growth     | production teams                 | higher platform fee + usage + optional implementation     | standard, limited concessions           |
| Enterprise | regulated/high-complexity buyers | annual commit, implementation required, custom order form | procurement + security packet mandatory |

### Not sold (do not promise)

- Custom feature roadmap commitments in order forms
- Unlimited bespoke integrations bundled into base subscription
- "Managed reconciliation team" as included support
- Any compliance certification not currently achieved

## Packaging dimensions

- Tenant/workspace scope (single tenant default, multi-tenant enterprise by contract)
- Monthly reconciliations and exception supervision load
- Operator seats and RBAC depth
- Integration profile (standard connector vs custom)
- Evidence retention/export scope
- Support and response tier
- Implementation depth

## Fee structure policy

- **Platform fee:** access, core workflows, baseline support
- **Usage fee:** reconciliation/exception volumes above inclusion
- **Implementation fee:** fixed-fee onboarding delivery for Growth/Enterprise where needed
- **Services fee:** explicitly scoped SOW work only

## Standard vs custom pricing

- Standard: Starter/Growth list prices, standard invoice terms, standard support boundaries.
- Custom: Enterprise only with approved exception record in `../03_Legal-Commercial/COMMERCIAL_POLICY_EXCEPTIONS_REGISTER.md`.

## Packaging anti-patterns

- One-off pricing for every deal
- Bundling unlimited support into low-ACV deals
- Hiding implementation labor in subscription fee
- Committing to undefined integration work without SOW

## Future expansion rules

- New package dimension requires: measurable usage event, billing system mapping, entitlement mapping, and close reporting impact.
- No new tier launched without SKU map and deal desk updates.
